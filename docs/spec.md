# Competitor Reels Tool: specification

## Purpose

Marketers and creators track Instagram competitors, collect their most recent
Reels in one library, and generate an editable breakdown of each Reel (hook,
script, call to action) to base their own content on.

## Users

A single user with no login. Anyone who can reach the app can use it.

## Core flows

1. **Track a competitor.** The user pastes an Instagram profile URL
   (`https://instagram.com/<name>`) or a bare `@username`. Invalid input shows
   an error. Adding the same username again returns the existing competitor
   and does not create a duplicate.
2. **Fetch Reels.** For a tracked competitor, the user fetches the 20 most
   recent Reels. Refetching replaces that competitor's Reels rather than
   adding to them.
3. **Browse the library.** The dashboard lists every stored Reel, newest first,
   with thumbnail, caption, views, likes, comments, and a link to Instagram.
4. **Remix a Reel.** The user generates a breakdown for a Reel: a title, hook,
   script, and CTA. Remixing a Reel that already has one opens the existing one.
5. **Edit a remix.** The user edits the title, hook, script, or CTA and saves.
   Only changed fields are sent to the server.
6. **Stop tracking.** Removing a competitor deletes its Reels and their remixes.

## Data

- **Competitor:** id, username, Instagram URL, display name, avatar URL, added time.
- **Reel:** id, competitor, shortcode, permalink, caption, thumbnail URL, view,
  like, and comment counts, posted time, fetched time.
- **Remix:** id, Reel, title, hook, script, CTA, created and updated times.

Data survives restarts (SQLite). The contract is in `openapi.yaml`.

## Out of scope for this version

- Fetching real Reels from Instagram. Sample data is generated by
  `backend/app/generator.py`.
- AI-written breakdowns. Remixes come from fixed templates in the same file.
- Accounts, authentication, and multiple users.
- Public deployment.
